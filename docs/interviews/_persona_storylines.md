## 0. 인터뷰에서 추출한 7가지 큰 발견

1. **모든 직무가 같은 페인을 다른 단어로 호소**: "**원인이 설명 안 됨**". 활성사용자수 변화는 결과인데 원인을 보여주는 데이터가 없음. (제작PD·CP·총괄·플랫폼전략 공통)
2. **CP가 정보 허브**: 위(국장)·아래(PD)·옆(데이터팀)으로 모든 흐름이 통과. 보고서 변환 노동의 진앙지.
3. **시간축이 두 종류로 분리됨**: 일/주(제작PD·CP·서비스운영) vs 분기(편성PD·플랫폼전략). 한 도구에 두 시간축이 공존해야 함.
4. **"무슨 지표를 봐야 할지 모르겠다"가 반복 등장** (제작PD·편성PD·CP·총괄): 셀프 큐레이션 한계. 떠먹이기형 디폴트 진입이 필수.
5. **사일로 두 곳**: 마케팅(외부 광고주 전용)·서비스운영(별도 도구)이 사내 다른 직무와 거의 정보 교환 없음.
6. **상황 인식 누락**: 제작PD가 "혼자만 인식하고 넘어가는 경우가 대부분" — 횡적 공유 자동화가 가치.
7. **폐쇄 루프 부재**: 편성PD가 "결정 후 다시 평가 안 함" 명시. 결정→재평가 흐름이 RAAS에서 만들어질 자리.

## 1. 직무별 핵심 정보 매트릭스

### 1.1 제작PD

| 항목 | 내용 |
|---|---|
| **주 시점** | 본인 담당 프로그램, 코너 단위 |
| **주 주기** | 일간(중요 프로그램) + 주간(코너 단위 패턴) |
| **반드시 필요한 정보** | 직전 회차 결과(±전주), 코너별 등락, 인접 시간대 비교, 특별 게스트/이벤트 회차 진단, 개편 전후 비교 |
| **있으면 좋은 정보** | 작가/진행자 공유용 자료, CP 보고용 변환 |
| **공통 페인** | 무슨 지표 봐야 할지 모름, 그래프 직관성 부족, 보고 자료 제작 어려움 |
| **개별 페인** | 모바일 미지원, 코너 단위 분석 부족, 게스트/선곡 분석 부재, 엑셀/메일 기능 부재 |
| **시그널 ◎** | 본인 프로그램 의존도, 코너 단위 분해, 일간 점검, 작가·진행자 공유, 옆 시간대 비교 |

### 1.2 편성PD

| 항목 | 내용 |
|---|---|
| **주 시점** | 채널 grid, 시간대 격자 |
| **주 주기** | **분기**(청취율 조사) 위주 + 일/주 보조 |
| **반드시 필요한 정보** | 채널별 시간대 grid, 분기 QoQ 비교, 시간대별 청취층(연령/성별/신규 유입) 변화, 정형 보고 자료 |
| **있으면 좋은 정보** | YoY 비교, "이 시간대에 ○○ 프로그램 가능한가" 가설 검증 |
| **공통 페인** | 채널마다 지표 정의가 달라 비교 힘듦, 결정 근거 약해 미룸, 비교 자료 제작 반나절 |
| **개별 페인** | 분기 단위 뷰 없음, 채널 grid가 KPI만 |
| **시그널 ◎** | 채널 grid, 분기·연간 비교, 정형 보고서, 즉답 채팅, 신규 유입 변화 |

### 1.3 CP (정보 허브)

| 항목 | 내용 |
|---|---|
| **주 시점** | 담당 프로그램군(N개) 동시, 시간대(출퇴근>낮>오전>저녁>심야) |
| **주 주기** | 일·주(스플렁크 활성사용자) + 분기(청취율 조사 랭킹) |
| **반드시 필요한 정보** | N개 프로그램 동시 비교, 변화 큰 회차 원인, 특별 게스트/이벤트 반응, 개편 전후 비교, PD 디스패치 메시지 |
| **있으면 좋은 정보** | 국장 보고용 자료, 사업국장 MAU 별도 보고(2026-06부터 신규 지시) |
| **공통 페인** | **변화 결과는 보이지만 원인 설명 못함** (가장 큰 아쉬움), 정형 보고 양식 없음, 데이터 의미 설명 들어야 알 수 있음 |
| **시그널 ◎** | N개 동시 비교, 보고서 변환 노동, 즉답 |

### 1.4 총괄관리

| 항목 | 내용 |
|---|---|
| **주 시점** | **국 전반 한 화면** (채널별 한 줄 요약) |
| **주 주기** | 주간 회의 보고 받음 + 필요시 면담 |
| **반드시 필요한 정보** | 국 전반 1화면 요약, 이상 신호 + 책임자 매핑, 임원 보고 정형 자료 |
| **있으면 좋은 정보** | 라디오 매체 규모 강조 자료(브랜드 파워 유지 입증) |
| **공통 페인** | 전사 통합 뷰 부재, 핵심 지표 부재, 원인 설명 부재 |
| **개별 페인** | 한눈에 안 들어옴, 책임자 매핑 부재 |
| **시그널 ◎** | 국 전반 1화면, 임원 보고 정형성 |

### 1.5 마케팅 (사일로)

| 항목 | 내용 |
|---|---|
| **주 시점** | 캠페인 단위(불규칙), 광고주 양식 |
| **주 주기** | 캠페인 + 월/분기 |
| **반드시 필요한 정보** | 도달(DAU 환산), 세그먼트(성별/연령), 캠페인 전후 A/B, 광고주 양식 출력 |
| **있으면 좋은 정보** | 앱 광고 인벤토리 집계, 가능 위치 예상 인벤토리, 과거 캠페인 비교(현재 유실됨) |
| **공통 페인** | 이전 캠페인 데이터 유실, 세그먼트 분석 부재 → 일반 평균치 제출, 광고주 양식 불일치 |
| **시그널 ◎** | 도달/노출 변환 노동, 세그먼트 분해, 캠페인 A/B, 즉답 |

### 1.6 플랫폼전략

| 항목 | 내용 |
|---|---|
| **주 시점** | 분기/연간, MAU 중심 |
| **주 주기** | **주간 임원회의 MAU 보고 (매주)** + 분기/연간 |
| **반드시 필요한 정보** | 고릴라 MAU 주간/분기 추이, YoY/QoQ |
| **있으면 좋은 정보** (미래 학습 영역) | 유입 채널 분석, 신규 코호트 D1·D7·M1 리텐션, 장기 vs 신규 사용자 행동 차이 |
| **현재 KPI 우선순위** | 활성사용자 > 사용자 흐름(신규/이탈/복귀) > 유지율 > 참여율 |
| **공통 페인** | 매주 스플렁크에서 수기 작성, 셀프서비스 부재, 사내 플랫폼 사일로 |
| **시그널 ◎** | 분기/연간, MAU 우선, YoY/QoQ, 즉답 |

### 1.7 데이터 (apollo 자가)

| 항목 | 내용 |
|---|---|
| **주 시점** | 전체>채널>프로그램별 모든 지표 |
| **주 주기** | 매일 |
| **반드시 필요한 정보** | 데이터 생성 유무·이상값 체크, 변동 큰 지표, 변동 설명할 지표 조합, 미해결 질의 |
| **자가 평가** | 매일 RAAS 사용. 다른 직무 질의/활용 기록으로 니즈 파악·직무-데이터 매핑하는 시스템을 만들고 싶음 |
| **차별점** | 떠먹이기 X → 자유 탐색 + 검증 모드 |

### 1.8 서비스 운영

| 항목 | 내용 |
|---|---|
| **주 시점** | **실시간 동시사용자** + 장애 + 앱 배포 |
| **주 주기** | 실시간(장애 시) + 일간 |
| **반드시 필요한 정보** | 실시간 동시사용자(현재 Splunk만), 장애 신호, 디바이스/OS/앱버전 배포 현황 |
| **있으면 좋은 정보** | 신규 사용자 습관형성률 ↑ 방안 (특별 게스트 후 푸시), 이벤트/UX 변경 전후 비교, 장애 발생/조치 기록 |
| **공통 페인** | RAAS와 운영 도구 분리, 운영 지표 부재, 이상 알림 부족 |
| **현재 활용** | Splunk 실시간 동시사용자, 공감로그(장애 글), 앱 배포 진행 현황 |
| **시그널 ◎** | 실시간 점검, 장애 디스패치, 기기·OS·앱버전 세그먼트, 콘텐츠팀 협업 수요 |

### 2.2 관찰된 5가지 순환 패턴

**패턴 1 — 상향 보고 사다리**
- 제작PD → CP (구두, 가끔 자료) → 국장 (자유 양식) → 본부장 (정형 보고)
- 편성PD → 국장 → 본부장 (분기 청취율조사 요약표)
- 플랫폼전략 → 임원회의 (매주 MAU)

**패턴 2 — 하향 디스패치**
- 총괄 → CP (주간 회의, 이상시 면담)
- CP → 제작PD (변화 큰 회차 즉각)
- 사업국장 → CP (특정 지시: 예 - MAU 별도 보고)

**패턴 3 — 데이터 의뢰의 시간 비용**
- 모든 직무 → 데이터팀(apollo) 의뢰
- 즉답 30% / 수시간~수일 70%
- 정형 포맷 없음 → 매번 수기 변환

**패턴 4 — 횡적 누락 (제작PD의 사일로)**
- 제작PD가 "혼자만 인식하고 넘어가는 경우 대부분"
- 상황 인식이 위(CP)나 옆(다른 PD)에 전파되지 않음

**패턴 5 — 폐쇄 루프 부재**
- 편성PD: "결정 후 다시 평가 안 함, 지난 보고서는 거의 안 봄"
- 결정 → 결과 평가 → 학습 흐름이 끊겨 있음

### 2.3 순환 구조의 함의

| 발견 | RAAS가 채울 수 있는 자리 |
|---|---|
| CP가 정보 허브 | CP 화면을 **격자 + 디스패치 메시지 생성기**로 |
| 데이터 의뢰 70% 지연 | 자주 묻는 질문을 **떠먹이기 카드**로 사전 답변 |
| 제작PD 횡적 누락 | "이번 변화를 CP와 공유" 1클릭 |
| 폐쇄 루프 부재 | 편성 결정 등록 → N주 후 자동 재평가 알림 |
| 사일로 두 곳(마케팅·운영) | 별도 진입 경로 + 자기 도구 안에서 사용 가능 |

## 3. 직무별 떠먹이기 스토리라인

각 스토리라인은 다음 구조를 따른다:
- **첫 화면**: RAAS가 먼저 던지는 질문/요약 (자기 자신 큐레이션)
- **1~5 단계 Q&A**: 사용자가 칩 클릭 또는 자유 입력 → RAAS 답변 → 다음 칩 제안
- **마무리**: 오늘 알아야 할 정보 다 얻었는지 자가 점검 + 보고/공유로 종결

### 3.1 제작PD 스토리라인 (5단계)

**디폴트 진입 = 본인 담당 프로그램의 직전 회차**

```
[1] RAAS  "○○ PD님 안녕하세요. [프로그램명] 직전 방송(○월 ○일) 끝났어요.
          청취자 반응을 보여드릴까요?"
          [네, 보여줘] [건너뛰기]

[2] RAAS  [직전 회차 1줄 요약: 활성사용자 N명 (전주 동요일 ±X%),
          코너별 등락 TOP3, 공감로그/문자 평소 대비 ±Y%]
          
          후속 칩 ↓
          • 어느 코너가 가장 반응 좋았어?
          • 전주 같은 회차와 비교해 줘
          • 인접 시간대([앞 프로그램]·[뒤 프로그램])는 어땠어?

[3] PD    "인접 시간대는 어땠어?"
   RAAS  [[앞 프로그램]: ±X%, [뒤 프로그램]: ±Y%, 유입/이탈 패턴 차이 해석]
          
          후속 칩 ↓
          • 우리 프로그램 강점이 뭐야?
          • 왜 차이가 났을까?

[4] RAAS  자발적 알림:

          - 공감로그/문자: 장애 관련 글 ○건 동시 발생
          
          → 앱 배포 이력과 대조: ○○시 ○○ 버전 배포 → 가능성 ◎"

[3] 운영  "지금 앱 배포 진행 중인 버전 영향 봐줘"
   RAAS  "[앱버전별 활성사용자 비중 + OS 분해]
          - 신버전 ○.○.○: 보급률 X%
          - 이상 신호: iOS 신버전에서 동시사용자 -Y% (조사 필요)"

[4] RAAS  자발적 제안 (Q4 답변 자동화):
          "최근 특별 게스트 ○○ 출연 후 유입된 신규 사용자 N명.
          이들의 습관형성률 ○% — 푸시 알람 대상자 자동 추출"
          [대상자 N명 CSV 다운로드] [푸시 시스템 연동]

[5] RAAS  "이벤트/UX 변경 전후 비교 자동화 + 장애 기록"
          [이벤트 등록] → 자동 전후 비교
          [장애 발생/조치 기록] → 향후 분석 시 자동 참고
```

**오늘 알아야 할 것 ✅** — 실시간 동시사용자·이상 신호 + 장애 가능성·배포 영향·신규 푸시·이벤트 비교·장애 기록

## 4. 8개 스토리라인의 공통 패턴

| 패턴 | 설명 |
|---|---|
| **시작 = 자동 큐레이션 한 줄** | 사용자가 "무엇을 봐야 할지" 고민할 필요 없음. 첫 화면이 답을 미리 제시 |
| **2~5단계 = 칩 클릭 또는 자유 입력** | 사용자가 다음 깊이를 선택. 칩은 인터뷰의 우선 탐사를 그대로 사용 |
| **자발적 알림 = 횡적 누락 해결** | 사용자가 묻지 않은 것을 RAAS가 먼저 던짐 (특별 게스트일, MAU 별도 보고 지시 등) |
| **마무리 = 보고/공유로 종결** | 카톡·메일·PNG·PPT 변환으로 닫힘 → "혼자 인식하고 끝나는" 페인 해결 |
| **원인 설명 우선** | 모든 답변에 "결과 + 추정 원인 + 근거 데이터" 3종 세트 |
| **책임자 자동 매핑** | 변화가 보이면 즉시 "담당 CP·PD" 표기 → 디스패치 1클릭 |

## 5. 직무별 첫 화면 디자인 요약 (와이어프레임용)

| 직무 | 첫 화면 핵심 | 변환 가능한 출력물 |
|---|---|---|
| 제작PD | 직전 회차 1줄 + 코너 TOP3 | 작가 카톡 / CP 자료 / PNG |
| 편성PD | 채널 grid (4×시간대) + 주목 셀 3 | 정형 보고서 / 비정형 분석 |
| CP | N개 프로그램 격자 + 변화 큰 회차 | PD 카톡 / 국장 PPT / MAU 별도 |
| 총괄관리 | 국 전반 4행 + 이상 신호 + 책임자 | 임원 PPT / 본부장 메일 |
| 마케팅 | 캠페인 카드 + 세그먼트 분해 | 광고주 양식 / 신규 제안 / 과거 비교 |
| 플랫폼전략 | MAU 주간 추이 + 임원 자료 | 임원 PPT / 분기 보고 / 통합 뷰 |
| 데이터 | 데이터 헬스 + 타 직무 수요 | 시스템 개선 우선순위 |
| 서비스 운영 | 실시간 동시사용자 + 24h 이상 | 푸시 대상자 / 이벤트 비교 |
