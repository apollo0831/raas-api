# 05. 총괄관리 — 인터뷰 1페이지

> 공통 원칙·도입·마무리: [README.md](README.md)
> 대상: 국 전반의 운영 건강·이상신호 책임을 진 임원/총괄 (국장·부국장 등)

---

## 페르소나 가설

- **시점**: 현재·운영 건강. **이상이 나면 누가 책임지나**를 가장 빨리 알고 싶음
- **주기**: 매일. 일간 점검은 사실상 의무
- **목적**: 이상신호 식별·책임자 디스패치·전사 보고
- **고통 가설**: 국 전반을 한 화면에서 보기 어렵고, 이상이 났을 때 **누구에게 물어볼지** 매번 다시 찾음

> 플랫폼전략(미래) vs 총괄관리(현재) 분리 — 동일인이라도 두 시점 중 하나에 집중하는 자리.

## 도입 후 첫 한마디

> "오늘은 국 전반의 청취 건강을 어떻게 모니터링하시고, 이상이 발견됐을 때 어떻게 대응하시는지 듣고 싶어요."

---

## Q1. 월요일 아침 행동 (5분)

**본 질문**: 지난 월요일 아침, 출근 후 30분 동안 국 전반의 청취 상태를 어떻게 확인하셨어요?

**총괄관리 우선 탐사**
- "이상 신호가 보이면 그다음 뭘 하세요?"
- "주말 회차 결과를 모아 확인하는 루틴이 있어요?"

**듣고 싶은 신호 (총괄관리)**
- ✅ "채널별 한 줄 요약 한 번에" — 국 전체 시점
- ✅ "이상이 있으면 담당 CP에게 즉시 메시지" — 디스패치
- ✅ "전주 대비 큰 변화부터" — Anomaly-first

---

## Q2. 데이터 출처와 조합 (5분)

**본 질문**: 국 전반을 한 번에 확인하실 때, 어떤 도구·자료를 보세요?

**총괄관리 우선 탐사**
- "전사 한 화면 요약 도구가 있어요?"
- "이상치를 자동으로 알려주는 게 있어요?"

**듣고 싶은 신호 (총괄관리)**
- ✅ "CP들이 메일로 보낸 요약을 모아봄" — 수기 통합
- ✅ "이상이 있어야 알게 됨, 자동 알림 없음"
- ✅ "분석팀 주간 보고서가 가장 신뢰" — 분석팀 의존

---

## Q3. 누구에게 어떻게 전달 (5분)

**본 질문**: 본 데이터를 누구에게 어떻게 전달·디스패치하세요?

**총괄관리 우선 탐사**
- "이상이 발견되면 누구에게 어떤 형식으로 알리세요?"
- "위로 보고하실 때(임원/사장단)는 어떤 형식이에요?"

**듣고 싶은 신호 (총괄관리)**
- ✅ "CP들에게 슬랙으로 즉시" — 빠른 횡적
- ✅ "임원 보고는 주간 1회" — 정형 보고
- ✅ "추가 질문 즉시 대응 필요" — 즉답 가능성

---

## Q4. 자주 묻는 질문 3개 (5분)

**본 질문**: 지난 한 달 동안 국 전반 운영에 대해 가장 자주 물었던 질문 3개는요?

**총괄관리 우선 탐사**
- "그 질문이 RAAS에 있다면 답이 나올까요?"

**듣고 싶은 신호 (총괄관리)**
- ✅ "지금 국 전체 상태가 양호한가?" — 정성 평가
- ✅ "○○ 채널이 왜 떨어졌어?" — 진단
- ✅ "누가 책임자야?" — 책임 매핑

---

## Q5. 짜증나는 순간 (4분)

**본 질문**: 데이터 관련 가장 최근 짜증났던 순간이 언제예요?

**총괄관리 우선 탐사**
- "그때 누가 옆에 있었다면 뭘 부탁했을 것 같아요?"

**듣고 싶은 신호 (총괄관리)**
- ✅ "갑자기 떨어졌는데 누구한테 물어볼지 헷갈려서"
- ✅ "보고 후에 잘못된 숫자였던 게 드러나"
- ✅ "전사 한 화면이 없어서 매번 모자이크"

---

## Q6. RAAS를 안 쓰는(잘 안 쓰는) 진짜 이유 (3분)

**본 질문**: 솔직히, RAAS를 (안 쓰셨다면) 왜 안 쓰셨어요?

**총괄관리 우선 탐사**
- "국 전반 한 화면 요약이 부족했나요?"
- "이상 알림이 없어서요?"

**듣고 싶은 신호 (총괄관리)**
- ✅ "한눈에 안 들어와서"
- ✅ "이상이 있을 때 알림이 안 와서"
- ✅ "책임자 정보가 함께 안 나와서"

---

## 페르소나 결정 시그널 체크리스트

| 시그널 | 강함 ◎ | 보통 ○ | 없음 ✕ |
|---|---|---|---|
| 국 전반 한 화면 시점 | | | |
| 이상신호 우선(Anomaly-first) | | | |
| CP·PD 디스패치 빈도 | | | |
| 일간 점검 빈도 | | | |
| 즉답 가능성에 대한 관심 | | | |
| 임원 보고 정형성 | | | |
| 책임자 매핑(누가 답할 사람) | | | |

**페르소나 결정 시 핵심 질문**: 총괄관리에게 RAAS는 **"국 전반 데일리 헬스 체크"** 도구인가? 그렇다면 브리핑 카드는 **이상신호 우선 + 책임자(또는 담당 CP) 자동 매핑**이 핵심.
