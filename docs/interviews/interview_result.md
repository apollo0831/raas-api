# **인터뷰 질문 답변 (데이터)**

| Q1. 월요일 아침 30분 | 출근 직후 사용 도구의 순서와 그 이유 분석 \=\> 스플렁크에서 전체\>채널\>프로그램별로 모든 지표 생성 확인 (생성 유무 및 수치 변동 확인, 전반적인 동향 및 특이사항 캐치) |
| :---- | :---- |
| **Q2. 데이터 출처와 조합** | 의존하는 데이터 소스 및 가장 병목이 발생하는 단계 파악  \=\> 스플렁크 데이터 중심. 모든 프로그램에 대해 모든 지표를 확인하는 것이 가장 오래 걸리는 작업. 한번에 확인하고 이상 있는 특이 데이터 위주로 심층 조사할 수 있으면 좋겠음. 심층 조사는 수치 변화의 원인을 설명할 수 있는 데이터를 찾는데 집중되어 있으나 관련성 있는 데이터를 찾기도, 필요한 데이터를 수집하기도 이미 수집된 데이터와 연관해서 분석하기도 쉽지 않다. |
| **Q3. 전달과 소통** | 타 팀의 질문 내용, 답변 시간, 정형 보고서 대비 즉답 비율  \=\> 즉답 비율은 30% 미만, 궁금한 현상을 확인해 달라는 쪽은 바로 스플렁크를 열고 관련 지표를 조회, 원인을 파악하거나 보고서를 만들어 달라는 요청은 시간이 걸림. 수시간\~수일 정도. 정형화된 포멧은 없음.  |
| **Q4. 자주 하는 질문 3개** | 본인의 탐색 질문과 타 팀의 수요 질문 간의 차이 분석 \=\> 생성되지 않거나, 이상한 값으로 생성된 데이터는 없는가? \=\> 변동이 특별히 큰 지표는 어떤 것들이 있었나? \=\> 그 지표의 변동 수치를 잘 설명할 수 있는 다른 지표(또는 지표들의 조합)은 어떤 것이 있는가? 없다면 어떤 설명을 위해 어떤 지표 또는 데이터가 추가로 필요한가? |
| **Q5. 페인 포인트** | 데이터 활용 중 가장 짜증나는 순간과 필요한 도구 가정 \=\> 데이터가 제대로 생성되지 않은 것을 발견했을 때, 현상을 설명할 어떤 데이터나 지표도 없을 때, 사용자들이 언제 어디서나 편하게 데이터 도구를 사용할 수 있도록 해주고 싶을 때  |
| **Q6. RAAS 자가 평가** | 본인 시스템을 매일 쓰는지, 안 쓴다면 솔직한 이유 기술 \=\> 나는 매일 쓰는데 데이터가 잘 생성되어 있는지 체크하고 어떤 지표를 만들어 내야하는지만 생각하는 것 같음. 지금 있는 데이터들을 잘 엮어서 각 직무의 사용자들이 실제 업무에 도움이 되도록 RAAS를 만들어 가고 싶음. 사용자들은 실제 속마음을 말하지 않기 때문에 질의와 활용 기록을 통한 니즈 파악, 직무와 필요 데이터 간의 관계를 파악함으로써 데이터 활용을 잘 할 수 있도록 이끌어 주는 시스템을 만들고 싶음.  |
