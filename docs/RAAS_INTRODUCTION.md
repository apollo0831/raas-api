## 1. 한 줄 정의 & 핵심 가치

> **RAAS(Radio Analytics)는 SBS 고릴라 라디오의 청취 데이터를 자연어 한 줄로 묻고, AI가 수치·차트·이상 알림·맞춤 추천까지 함께 답해 주는 직무 맞춤형 AI 분석 어시스턴트입니다.**

| 가치 | 의미 |
|---|---|
| **자연어 한 줄** | "어제 DAU는?" "철파엠 유지율 현황" 같은 평범한 한국어로 질의 |
| **AI 해석 + 시각화 동시** | 단순 숫자가 아닌 "왜 그런지·무엇을 봐야 하는지" 분석 + 자동 차트 |
| **직무 맞춤** | 제작 PD·편성 PD·CP·플랫폼전략·총괄관리·데이터·서비스운영·마케팅 — 직무별로 다른 첫 화면·추천 |
| **점진적 개인화** | 사용 이력이 쌓일수록 "당신이 안 본 것 중 봐야 할 것"을 능동적으로 제안 |

## 2. 탄생 배경 & 비전

### 기존 운영의 문제
- Splunk 대시보드에서 PD·편성·마케팅 담당자가 직접 지표를 찾고 해석해야 했음
- 지표가 너무 많고 정의가 직관적이지 않음 (DAU·D1유지율·습관형성률·이탈율·실청취율 등 30+ 종)
- 채널·프로그램·기간 조합을 매번 수동으로 필터링
- "어제 이상한 거 있어?" 같은 자연스러운 질문에 답하려면 여러 화면을 오가야 함

### RAAS의 비전
**"직무 맞춤 AI 분석 동료"** — 단순 대시보드가 아니라, 사용자의 직무·관심사·맥락을 이해하고 함께 고민해 주는 AI 동료.

세 가지 핵심 축:
1. **묻기 쉽게** — 자연어 질의 + 직무 기반 추천 칩
2. **숨은 신호 발굴** — 이상 감지 + 사각지대 추천 + 관계 그래프
3. **공동 학습** — 질문자 맵으로 "누가 무엇을 묻는지"를 학습해 다시 추천에 반영

## 3. 5단계 진화 로드맵

| 단계 | 내용 | 상태 |
|---|---|---|
| **Phase 0** | 자연어 질의 엔진 + 일일 브리핑 + 차트 시각화 | ✅ 완료 |
| **Phase 1** | 사용자 관리 (가입→승인→로그인, 직무 7+1종) | ✅ 완료 |
| **Phase 2** | 질의 ETL (intent/scope/metric/role/topic_key를 fact로 적재) | ✅ 완료 |
| **Phase 3** | 직무 맞춤 온보딩 (role_profiles.json + 추천 칩) | ✅ 완료 |
| **Phase 4** | 관리자 질의맵 통계 페이지 (집계·히트맵) | ✅ 완료 |
| **Phase 5** | 추천 엔진 (갭 분석 + 동료 인기 + 코사인 유사 사용자) | ✅ 완료 |
| **Phase 6** | 관계 그래프 + co-query + 개인 관심 맵 | ✅ 완료 |
| 향후 | 직무 ML 클러스터링, 실시간 동접, 게스트 효과 심화 분석 | 예정 |

| 모듈 | 책임 |

- CORS 안전: 브라우저가 Splunk·Claude를 직접 호출하지 않고 서버 경유

## 5. 핵심 기능 상세

### 5-1. 자연어 질의 엔진 (3단계 파이프라인)

```
사용자 질문
   ↓
[1단계] classify_intent() — Claude가 질문을 13가지 intent로 분류
   ↓ JSON: {intent, scope, metric, metrics?, date_type, days, scope_keyword?}
[2단계] extract_data() — intent별로 다른 SPL 실행 + 로컬 CSV 폴백
                       + 온톨로지에서 프로그램·진행자·공휴일 컨텍스트 자동 주입
   ↓
[3단계] call_claude() — Sonnet/Opus가 컨텍스트를 해석해 자연어 답변 생성
   + build_chart_data() — 인텐트에 맞는 자동 차트 생성
   ↓
SSE 스트리밍으로 브라우저에 토큰 단위 전송
```

**Intent 13종 분류:**

| Intent | 예시 질문 |
|---|---|
| `snapshot` | "어제 DAU는?" |
| `trend` | "최근 30일 DAU 추이" |
| `compare` | "어제 채널별 이탈율 어디가 제일 높아?" |
| `compare_trend` | "파워FM vs 러브FM DAU 추이 비교" |
| `dual_trend` | "최근 DAU와 깊은청취율 동시에" |
| `ranking` | "프로그램별 DAU 순위" |
| `overview` | "프로그램별 전 지표 한눈에" |
| `health` | "위험 프로그램 있어?" |
| `funnel` | "신규/복귀/이탈 비율" |
| `engagement` | "깊은청취율 추이" |
| `growth` | "습관형성률 어때?" |
| `anomaly` | "오늘 이상 알림" |
| `report` | "전체 현황 요약" |
| `general` | 그 외 |

### 5-2. 자동 일일 브리핑 (7개 섹션)

매일 아침 Splunk 갱신(06:50) 후 7개 섹션으로 리포트 자동 생성:

| 섹션 | 키 | 내용 |
|---|---|---|
| Executive | `s1_executive` | DAU/WAU/MAU + WoW |
| Funnel | `s2_funnel` | D1/D7/W1/M1 유지율, 신규·복귀·이탈 비율 |
| Engagement | `s3_engagement` | 깊은청취율(10분↑), 실청취율(1분↑), 참여율 |
| Growth | `s4_growth` | 습관형성률, TOP3 프로그램 |
| Rankings | `s5_rankings` | DAU TOP10, 깊은청취 TOP5, 리스크 프로그램 |
| Channels | `s6_channels` | 파워FM·러브FM·고릴라M·픽채널 채널별 비교 |
| Anomalies | `s7_anomalies` | **Z-score 기반 이상 알림** (red/yellow/green 신호등) |

### 5-3. 차트·시각화 (4가지 타입 자동 선택)

질문 유형에 맞춰 자동으로 적절한 시각화:

| 차트 타입 | 사용 예 |
|---|---|
| `timeseries` | DAU 30일 추이 |
| `timeseries_multi` | 파워FM·러브FM DAU 동시 추이 |
| `timeseries_dual` | DAU와 깊은청취율 이중 Y축 |
| `comparison` | 채널별 깊은청취율 막대 |
| `table` | 프로그램별 종합 지표 |
| `multi_chart` | 전체+신규 코호트 유지율 한 답변에 둘 다 |
| `ranking_table` | TOP10 순위 |
| `overview_table` | 편성시간 순 종합 현황 |

규칙 기반 차트가 다루지 못하는 질문은 **Claude AI가 직접 차트 스펙(JSON)을 생성하는 폴백**이 처리 — "출처: AI 생성 차트" 라벨로 구분.

### 5-4. 직무 맞춤 추천 칩 (온보딩 MVP)

환영 화면(질의 시작 전)에서 사용자에게 **"오늘 알아야 할 것"**을 4가지 출처로 추천:

| 소스 | 시각 단서 | 우선순위 점수 | reason 문구 |
|---|---|---|---|
| **🔴 이상신호 (anomaly)** | 빨강/노랑 강조색 | 최상단 | "🔴 복귀율 -6.80 (z=-3.6)" |
| **💡 사각지대 — 템플릿 갭** | 보라 톤 + 💡 | 3.0 | "{직무} 직무에서 자주 살펴보는 주제예요" |
| **💡 사각지대 — 지표 갭** | 보라 톤 + 💡 | 2.5 | "{직무} 직무에서 챙기기 좋은 지표예요" |
| **👥 동료 인기 (peer)** | 그린 톤 + 👥 | 2.0 | "같은 직무 동료들이 자주 살펴보는 주제예요" |
| **✦ 유사 사용자 (similar)** | 액센트 + ✦ | 1.5 | "관심 분포가 비슷한 동료가 본 주제예요" |
| **검색 아이콘 (profile)** | 일반 알약 | 1.0 | (기본 템플릿, reason 없음) |

칩 클릭 → 기존 `submitQuery(질문)` 직접 호출 → 평소처럼 답변·차트 스트리밍.

**임계점 (콜드스타트 안전):**
- peer: 같은 직무 사용자 ≥1명일 때만
- similar: 같은 직무 사용자 ≥3명 + 코사인 유사도 ≥0.2

### 5-5. 관리자 질의맵 통계 페이지

권한 있는 직무(시스템관리자 + 총괄관리 + 데이터)만 우측 사이드바 하단 **"질의맵"** 버튼으로 접근. 모달 내 6개 탭:

| 탭 | 내용 |
|---|---|
| **전체** | KPI 카드 4개 (총 질문수·활성 사용자·총 토큰·평균 토큰) + 일별 추이 스파크라인 |
| **직무별** | 직무 × (질문수·사용자수·평균 토큰·주 intent/metric/scope) 막대+테이블 |
| **사용자별** | 사용자 × (직무·질문수·토큰·피드백·대표 주제·마지막 활동), 본인 행은 강조 |
| **인기 주제** | `topic_key` 빈도 TOP + 질문 텍스트 빈도 TOP |
| **관계 (히트맵)** | 직무 × 지표/scope 농도 히트맵 (지표↔scope 차원 토글) |
| **그래프** | 사용자/직무/지표/대상 노드 + 4종 엣지 인터랙티브 그래프 |

기간 토글: 7일 / 30일 / 전체.

### 5-6. 관계 그래프 (Phase 6 — vanilla JS force simulation)

외부 의존성 0의 자체 구현 force simulation:

**노드 4종:**
- 🟢 사용자 (원, 직무 색)
- ⬡ 직무 (육각형, 직무 색)
- 🟦 지표 (사각형, 액센트 블루)
- 🔷 대상 (다이아몬드, 그린)

**엣지 4종:**
- `membership`: user → role (회색)
- `interest`: user → metric/scope (액센트 블루, 가중치 = 빈도)
- `co_query`: metric—metric, scope—scope (시안, 같은 사용자/같은 날 함께 등장 빈도)
- `similar`: user—user (보라 점선, 코사인 유사도 ≥0.2 & 같은 직무 ≥3명)

**인터랙션:**
- 노드 드래그로 위치 고정
- 빈 영역 드래그로 팬, 휠로 줌
- 노드 클릭 → 사이드 패널에 노드 정보 + 인접 노드 + 가중치

**Force 시뮬레이션:**
- 척력 (Coulomb-like, 1/r²)
- 인력 (엣지 스프링, 가중치 로그 스케일)
- 중앙 gravity + Euler 적분 + 댐핑
- 150 iter 초기 안정화 후 정적

### 5-7. 개인 관심 맵 (Phase 6)

모든 로그인 사용자가 **내 정보 모달**에서 자기 데이터만 확인:

- **KPI 카드**: 최근 30일 질의수 + 직무 + 주요 주제
- **막대 차트 2개**: 주로 보는 지표 / 주로 보는 대상
- **사각지대 (💡 보라 칩)**: 직무 프로필 기대 영역 중 미열람 항목 — 추천 엔진의 `gap`/`gap-metric` 재사용
- **동료 평균 대비** (같은 직무 ≥3명일 때만): 내 질문수 vs 평균, 동료가 자주 보는 지표

**프라이버시:**
- 라우트가 **항상 세션 user_id로만** 동작 → 다른 사용자 데이터 위조 불가

## 6. 지표 체계

`raas_rules.md`에 명시된 **4범주 분류** — 모든 답변이 이 분류 체계를 따르도록 규정:

| 범주 | 주요 지표 |
|---|---|
| **사용자 규모** | DAU, WAU, MAU, 신규 사용자, 1분↑ 청취자, 10분↑ 청취자 |
| **사용자 흐름** | 신규/복귀/이탈 비율, D1·D7·W1·M1 유지율 (전체/신규 코호트), 리텐션 |
| **청취 품질** | 깊은청취율(10분↑), 실청취율(1분↑), 참여율, 몰입도 |
| **유지율** | 복귀율, 습관형성률 |

### 채널·프로그램 코드 체계
- **채널**: T00(전체), F00(파워FM), L00(러브FM), G00(고릴라M), P00(픽채널)
- **프로그램**: F01~F13 (파워FM), L01~L15 / M05~M11 (러브FM)
- 답변에서 코드 단독 표기 금지 — 항상 **"프로그램명(코드)"** 형식 (예: 시선집중(F06))

### 권한 분리 (시스템 vs 업무)
- **업무 직무**는 사용자 선택. 추천·통계 라우팅에 사용
- **시스템 관리 권한**은 별도 `users.is_admin` 플래그 — `.env`의 `ADMIN_LOGIN_IDS`(현재 apollo만)로만 부여
- 즉, "총괄관리" 직무라도 시스템 관리자가 아니며, "데이터" 직무여도 apollo는 시스템 관리자

### 권한 매트릭스

| 기능 | 권한 |
|---|---|
| 질의·차트·이력 | 모든 승인 사용자 |
| 내 정보 / 내 관심 맵 | 본인 데이터만 (세션 기반) |
| 승인 관리 (`/api/admin/users`, `/admin/approve`) | `is_admin` 만 |
| 통계 페이지 (`/api/admin/stats/*`) | `is_admin OR role in {총괄관리, 데이터}` |
| `/api/ip-users` | `is_admin` 만 (감사용·하위호환) |

### 인증 메커니즘
- **비밀번호**: `hashlib.pbkdf2_hmac('sha256', salt=16바이트, iter=200,000)`
- **세션 토큰**: `secrets.token_urlsafe(32)`, 만료 30일
- **헤더**: `Authorization: Bearer <token>`
- 401 응답 시 프론트가 자동으로 로그인 게이트로 복귀

### 가입 → 승인 → 로그인 워크플로
1. 사용자가 가입 폼 작성 (login_id, password, name, role 6종 드롭다운)
2. `status='pending'` 으로 DB 저장
3. 시스템 관리자(apollo)가 **승인 관리** 모달에서 승인/거절
4. 승인 시 `status='approved'` + 로그인 가능
5. `.env`의 `ADMIN_LOGIN_IDS`에 있는 login_id로 가입하면 자동 승인 + `is_admin=1` (부트스트랩)

### 프롬프트 캐싱
- 정적 시스템 프롬프트 + `raas_rules.md` 운영 규정을 `cache_control: ephemeral`로 표시
- 5분 TTL로 동일 사용자 연속 질의 시 입력 토큰 70%+ 절감
- 동적 블록(날짜·intent별 노트·차트 중복 금지 노트)은 캐시 밖

### 스트리밍 (SSE)
- `/api/query/stream` 엔드포인트에서 토큰 단위 실시간 전송
- 차트 데이터는 `meta` 이벤트로 텍스트 시작 전에 먼저 전송 → UI 사전 렌더링 가능

### 새 Claude API 호출 0건 원칙
- Phase 4·5·6의 모든 통계·추천·그래프는 **순수 SQL + 표준 라이브러리**로 처리
- `classify_intent` 결과는 ETL 단계에서 fact로 저장해두고 재활용 → 통계가 추가 토큰을 쓰지 않음

## 10. 온톨로지 — RAAS의 두뇌

`raas_onto/`의 RDF 기반 지식 그래프 — 단순 사전이 아니라 **관계 기반 추론** 지원.

### 표현 대상

| 엔티티 | 속성 |
|---|---|
| **Program** | code, 정식명, 별명들, 소속 채널, 방송 시간대, 진행자, 고정 게스트 |
| **Person** | label, 직업, 출연 프로그램 |
| **DayType** | 평일/주말/공휴일 (공휴일명 포함) |
| **Event** | 선거일·명절 등 특수일 |
| **TimeSlot** | 방송 시간대 + Daypart(아침·저녁) |

### 활용 예
- **프로그램 별명 해소**: "철파엠" → F06(영철파워FM)으로 자동 매핑
- **공휴일 보정**: 어제가 공휴일이면 청취 감소를 정상 패턴으로 명시
- **게스트 효과**: `find_top_guests(F06, days=30)` → 정상근 +5.2%, 이재익 +3.8% 같은 효과 자동 계산
- **Z-score 이상 감지**: `evaluate_zscore_alerts(timeline, ref_date)` → s7_anomalies 핵심 엔진

### 컨텍스트 자동 주입 (`raas_briefing_context.py`)
질문에 따라 동적으로 5종 블록 주입:
- **A. 지표 정의 블록** (분석·인사이트 intent만)
- **B. 프로그램·인물 메타 + 게스트 효과** (질문에 프로그램명·인물명 매칭 시)
- **C. 게스트 데이터 해석 규칙** (게스트 질의 시)
- **D. DayType 컨텍스트** (공휴일·주말 패턴 해석 오류 방지)
- **E. 연속 추세 감지** (3일 이상 연속 변화)
- **F. 위험 프로그램 목록** (risk/health intent)

## 13. 기술 스택 & 운영 환경

### 백엔드
- **언어**: Python 3
- **표준 라이브러리만** (외부 패키지 최소화):
  - `http.server.ThreadingHTTPServer`
  - `sqlite3`
  - `hashlib`, `secrets`, `urllib`, `json`, `re`, `math`
- **외부 패키지**: `python-dotenv`, `pandas` (CSV 폴백)
- **DB**: SQLite (`raas_history.db`) — 운영 데이터는 .gitignore

### 프론트엔드
- **Vanilla JS + CSS** (프레임워크 0)
- **SVG** 기반 자체 차트 렌더러 (timeseries·comparison·heatmap·force graph)
- **SSE** 스트리밍 수신
- **localStorage** 캐시
- 외부 의존성: xlsx 다운로드용 1개 (lazy CDN 로딩, 핵심 기능과 무관)

### AI
- **Anthropic Claude API** 직접 HTTPS 호출 (`urllib.request`)
- 사용 모델: Opus 4.7 / Sonnet 4.6 / Haiku 4.5
- 프롬프트 캐싱 활용 (5분 TTL)

### 데이터 소스
- **Splunk REST API** — KPI 룩업 테이블
- **로컬 CSV 폴백** — `data/raas_kpi_latest.csv`
- 매일 06:50 갱신

## 14. 향후 방향

### 단기 (Phase 7 후보)
- **답변 뒤 후속 후크 칩**: "방금 답변에서 더 깊이 볼 만한 후속 질문" 자동 제안
- **개인용 일일 요약 이메일**: 각 사용자에게 직무 맞춤 일일 브리핑 자동 발송
- **알림 구독**: 특정 프로그램·지표 이상 감지 시 푸시

### 중기
- **데이터 소스 확장**: 실시간 동접, 선곡표, 게스트 출연 메타, 공감 로그
- **음악 큐레이션 AI**: 선곡 패턴과 청취 효과 연관 분석
- **ML 기반 직무 클러스터링**: 사용자가 100명+ 되면 직무 외 자연 군집 자동 발견

### 장기
- **외부 데이터 통합**: 광고 인벤토리, 협찬 단가, 시장 데이터
- **편성 시뮬레이션**: "이 시간대에 이 프로그램을 옮기면?" 가상 실험
- **다국어 지원**: 영어/일본어 (필요 시)
